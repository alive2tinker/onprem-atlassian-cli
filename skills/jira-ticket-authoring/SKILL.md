# Jira Ticket Authoring

Use this skill when the user wants a new Jira ticket drafted or refined before creation.

## Workflow

1. Identify ticket type: bug, story, task, epic, subtask, spike, incident, or change.
2. Draft summary, context, problem statement, scope, acceptance criteria, and test notes.
3. For bugs, include observed behavior, expected behavior, reproduction steps, impact, environment, and evidence.
4. For stories, include user value, constraints, acceptance criteria, and dependencies.
5. Create the Jira issue only if the user asks you to create it.

## Style

Use concise, skimmable Jira formatting. Keep acceptance criteria testable.
